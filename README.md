Небольшой модуль для Foundry VTT v14 + dnd5e, который чинит проблемы совместимости русской локализации с Midi-QoL, Cauldron of Plentiful Resources и Coven's Automation Toolkit (CAT).

Релиз 14.0.0 предназначен для Foundry 14 / dnd5e 6. В манифесте указана совместимость с Foundry 14; Foundry 13 не примет этот релиз как совместимое обновление. Для Foundry 13 используйте предыдущую совместимую версию 13.x. Старые обработчики сохранены в исходниках.

## Что чинит

### Midi-QoL Active Effects

При русской локализации некоторые автоматизации создают Active Effect с ключом вида:

```text
flags.midi-qol.disadvantage.check.сил
```

Вместо корректного системного ключа:

```text
flags.midi-qol.disadvantage.check.str
```

Midi-QoL такие ключи не понимает, поэтому эффект может не работать. Модуль перехватывает создание и обновление Active Effects и заменяет русские сокращения характеристик/навыков на системные dnd5e-коды.

Работает на хуках:

- `preCreateActiveEffect`
- `preUpdateActiveEffect`
- `preCreateItem`
- `preUpdateItem`
- `preCreateActor`
- `preUpdateActor`

На v14 обрабатывается `system.changes`, включая эффекты внутри создаваемых и обновляемых предметов и актёров. В коде также сохранён обработчик старого формата `changes`. При создании берётся актуальное состояние документа после DAE. Меняются ключи изменений и соответствующих записей `flags.dae.inlineRolls`, чтобы переносимые эффекты сохраняли результаты уже выполненных бросков. Значения, типы изменений, формулы, длительности и остальные флаги сохраняются.

Исправление ограничено ключами Midi-QOL и системными путями характеристик, навыков и бонусов. В Midi-флагах `skill` допускаются и навыки, и характеристики: неоднозначное `лвк` остаётся без изменений. Используйте полное название «Ловкость» для `dex` или «Ловкость рук» для `slt`.

### CAT / Chris's Premades 2.x

CAT ищет автоматизацию предмета по `system.identifier`. Например, предмет Лаару `Шоковое прикосновение / Shocking grasp` может иметь identifier `shokovoe-prikosnovenie--shocking-grasp`, хотя автоматизация зарегистрирована как `shocking-grasp`.

Для предметов в мире и на актёрах модуль добавляет fallback в `cat.utils.documentUtils.getIdentifier`:

- корректный зарегистрированный identifier имеет приоритет;
- fallback разрешён для пустого identifier или identifier, совпадающего с системным преобразованием полного названия;
- кандидаты берутся из явно указанной латинской части названия и исходного имени Babele, если оно доступно;
- разбор двуязычного названия требует кириллицы; скобки обычного английского названия не считаются переводом;
- соответствие проверяется по действующему реестру CAT с учётом типа предмета, источника способности и монстра;
- при нескольких различных канонических identifiers результат остаётся штатным;
- CAT продолжает самостоятельно фильтровать редакцию правил, выбранный источник и исключённые источники.

Fallback применяется при чтении и сам не записывает identifier, имя или другие поля предмета. Штатный CAT Apply/Update может записать канонический identifier из исходной автоматизации, сохраняя перевод по своим правилам. Индексы и исходные предметы компендиумов не переназначаются.

Для копий предметов в мире и на актёрах поиск игнорирует конечные суффиксы `(копия)` и `(Copy)`, включая повторения и варианты вроде `(копия 2)`. Учитываются identifiers, сохранённые от исходного предмета или сгенерированные после промежуточного копирования. Название не меняется. Пользовательские identifiers и уже зарегистрированные автоматизации сохраняют приоритет; обычные уточнения вроде `(2024)` не удаляются.

Используется текущий реестр без кеширования промахов, поэтому поздняя регистрация CPR и переключение источников учитываются при следующем поиске. Поиск, Apply/Update, конфигурация и внутренние вызовы массовых операций получают общий identifier.

Целевая установленная связка: Foundry 14.369, dnd5e 6.1.1, Midi-QOL 14.7.1, CPR 2.1.10, CAT 0.1.9, DAE 14.6.10. Поддержка других версий зависит от сохранения используемых API.

В 14.0.2 исправлен общий поиск CAT в компендиумах: `getDocumentsBySlug` и `getDocumentByName` учитывают исходные имена Babele и английские части двуязычных названий. Исправление применяется к существам, предметам и другим документам, которые автоматизация ищет этими методами. Оно покрывает, в частности, Find Familiar, Find Steed, Flock of Familiars и поиск существа для Feline Form. Порядок результатов, точные совпадения внутри выбранного компендиума и фильтр редакции правил сохраняются; неоднозначные переводы пропускаются. Поиск по стабильным identifiers, пользовательские папки и предупреждения о действительно отсутствующих документах не изменяются.

Если активен **Laaru•Compendium•DnD14** (`laaru-dnd5-hw`), для призыва из стандартного `dnd5e.monsters` сначала проверяются его компендиумы актёров. Из Лаару берутся только звери с точным совпадением английского имени или его сохранённого оригинала. Для отсутствующего, недоступного или неоднозначного варианта используется стандартный компендиум с описанным выше исправлением локализации. Указанная вручную папка призыва имеет приоритет. Лаару остаётся необязательным модулем.

В рамках одного поиска каждый нужный индекс обрабатывается один раз. Поиск одного имени останавливается на точном совпадении; для списка строятся карты только запрошенных имён. Полные документы загружаются только для выбранных записей, каждый UUID — не более одного раза. Исходное имя Babele запрашивается явно, в том числе для сохранённых переводов в пользовательских компендиумах. Используется встроенный кеш индексов Foundry; результаты поиска не сохраняются между запросами, чтобы изменения переводов и компендиумов учитывались сразу.

### Cauldron of Plentiful Resources

CPR ищет автоматизации по английскому имени или внутреннему identifier. Из-за этого предмет с названием вроде `Сглаз / Hex` может не определяться через Medkit, хотя автоматизация для `Hex` есть.

Модуль добавляет CPR fallback-поиск:

- исходное имя;
- части двуязычного имени через `/`, `|`, `\`;
- текст в конце в круглых или квадратных скобках;
- CPR identifier, если он найден по одному из вариантов имени.

Пример:

```text
Сглаз / Hex
```

будет проверяться как:

```text
Сглаз / Hex
Сглаз
Hex
```

Если CPR установлен и активен, модуль скрывает известное ложное предупреждение CPR:

```text
Предмет в компендиуме не найден! chris-premades.CPRSpells: Fire Shield
```

Скрывается только точный текст этого предупреждения и только когда индекс компендиума содержит Fire Shield, его английский alias или CPR identifier. Если предмет реально отсутствует, индекс недоступен или сообщение относится к другому предмету, предупреждение остаётся.

Подавление относится только к старому CPR 1.x. Уведомления CAT не подавляются.

## Настройки

В настройках Foundry доступны:

- **Active Effects** - внутреннее меню с логированием исправленных и проверенных Active Effect keys.
- **CPR / CAT** - внутреннее меню с fallback-поиском CPR/CAT и скрытием известных ложных предупреждений CPR 1.x. Существующие ключи настроек сохранены.
- **Skill Tree** - внутреннее меню синхронизации страниц Skill Tree из первого связанного предмета. Можно отдельно включить синхронизацию названия, изображения и описания.

Для настроек есть английская и русская локализация:

- `languages/en.json`
- `languages/ru.json`

## Диагностика

Модуль экспортирует небольшой API:

```js
const api = game.modules.get("midi-locale-fix").api;
```

Проверить исправление Midi-QoL ключа:

```js
api.fixKey("flags.midi-qol.disadvantage.check.сил");
// "flags.midi-qol.disadvantage.check.str"
```

Проверить варианты поиска CPR:

```js
api.testCPRName("Сглаз / Hex");
// { name: "Сглаз / Hex", candidates: ["Сглаз / Hex", "Сглаз", "Hex"] }
```

Проверить CAT-поиск для предмета на выбранном токене:

```js
const item = canvas.tokens.controlled[0].actor.items.find(i => i.name.includes("Shocking"));
api.testCATItem(item);
// { identifier: "shokovoe-prikosnovenie--shocking-grasp",
//   resolved: "shocking-grasp", reason: "nameFallback", candidates: [...] }
```

`reason` показывает штатный результат (`native`), fallback (`nameFallback`), пользовательский identifier (`customIdentifier`), отсутствие реестра (`registryUnavailable`), промах (`notFound`) или неоднозначность (`ambiguous`). `api.runDiagnostics()` также показывает версии интеграций, установленный CAT-патч, готовность и размер реестра.

Проверить suppression warning:

```js
api.isSuppressedCPRWarning("Предмет в компендиуме не найден! chris-premades.CPRSpells: Fire Shield");
// true только при наличии предмета или его CPR identifier в индексе компендиума
```

## Dependencies

Модуль рассчитан на систему **dnd5e**. В манифесте указаны обязательные зависимости **Midi-QOL** и **Chris's Premades** (CPR, минимум 1.5.27). Foundry предлагает установить их при установке модуля и требует включить их при его активации.

Остальные обязательные модули устанавливаются по цепочке зависимостей выбранной версии Midi-QOL и CPR:

- **DAE**, **socketlib**, **libWrapper** — требования автоматизаций;
- **CAT** — требование CPR 2.x для Foundry 14.

**Skill Tree** — необязательная интеграция для синхронизации страниц дерева навыков; в рекомендациях манифеста он не указан. Обработчики старого CPR 1.x сохранены в исходниках; эта ветка использует Times Up и работает без CAT.

Версия 14.0.0 допускается только на Foundry 14. Совместимость системы dnd5e и сторонних автоматизаций с выбранной Foundry определяется их собственными манифестами и API.

## Релизы

После push в `master` workflow сам проверяет модуль, собирает `midi-locale-fix.zip`, создаёт тег `v<version>` и draft-релиз с архивом и `module.json`. Также можно запустить его вручную на `master`. Версия берётся из `module.json`; тег создавать вручную не нужно.

Повторный запуск обновляет файлы draft-релиза. Пустой опубликованный релиз восстанавливается как draft; опубликованный релиз с вложениями пропускается. Для следующего релиза нужно изменить `version` и соответствующий тег в `download`, закоммитить и отправить изменения. Готовый draft публикуется кнопкой Publish release в GitHub.
